Trial Trap: app map

A short guide to where things live in the code, so you know where to start when you want to change something. Snapshot of commit d7fa420.

What the app is made of

Trial Trap reads free-trial emails you paste and shows what's about to charge you, when, how much, and how to cancel. It has four main pieces:

  • The page (public/) is what you see in the browser. It draws the cards and the banner, makes the calendar reminders, and remembers your trials.
  • The helper server (server.js) runs on your laptop when you type npm start. It sends the page to the browser and reads emails at /api/extract.
  • Two readers (lib/). The smart reader asks an AI model hosted by NVIDIA. The built-in reader looks for patterns and needs no AI. Both answers go through one checker before reaching the page.
  • Browser storage (localStorage) is where your trials are remembered. Nothing is stored on the server.

One action, start to finish: clicking “Find my trials”

  1. The page reads the text box and sends it, with today's date, to the server.
  2. The server uses the smart reader if .env has an NVIDIA key. If there's no key, or the AI fails, is slow, or answers in the wrong shape, it uses the built-in reader instead.
  3. Whichever reader answered, every trial is checked: real dates, sensible prices, and only http/https links.
  4. The page adds the trials it hasn't seen before, saves them in the browser, and draws a card for each one.

Stop 2 · the server picks a reader

server.js → search for app.post('/api/extract' (line 25)

With a key it tries aiExtract. If that throws for any reason, the catch uses basicExtract and adds a small note, so the page always gets an answer. To see exactly what the AI is asked to do, look at INSTRUCTIONS in lib/aiExtract.js.

Show the code
app.post('/api/extract', async (req, res) => {
  const text = typeof req.body?.text === 'string' ? req.body.text : '';
  const today = isValidISODate(req.body?.today) ? req.body.today : todayISO();

  if (!text.trim()) {
    return res.status(400).json({ error: 'Paste an email first, or try the sample emails.' });
  }
  if (text.length > MAX_TEXT_LENGTH) {
    return res.status(413).json({ error: 'That is a lot of text. Try pasting fewer emails at a time.' });
  }

  if (ai) {
    try {
      const { trials, ignoredCount } = await aiExtract(text, today, ai, aiOptions);
      return res.json({ trials, ignoredCount, mode: 'ai' });
    } catch (error) {
      // Never log the pasted text or the key, only what went wrong.
      console.warn(`Smart reading failed (${error.name === 'AIError' ? error.message : error.name}), using the built-in reader.`);
      const { trials, ignoredCount } = basicExtract(text, today);
      return res.json({ trials, ignoredCount, mode: 'basic', note: FALLBACK_NOTE });
    }
  }

  const { trials, ignoredCount } = basicExtract(text, today);
  return res.json({ trials, ignoredCount, mode: 'basic', note: BASIC_NOTE });
});

After any change, run npm test. If all the tests still pass, the rest of the app still works.

A practice to reuse: plan for the AI failing, and test that plan without the AI

The decision. Before any code was written, devpost/spec.md said what happens when the AI can't help. With no key, an error, a rate limit, a 20-second timeout, or an answer in the wrong shape, the app uses the built-in reader instead.

The evidence. test/ai.test.js → search for falls back when NVIDIA is busy (line 112). These tests start a fake NVIDIA server that answers nonsense, says it's busy, or is too slow. Each time, they check the app still finds the three sample trials. The real NVIDIA service couldn't be reached from the computer the app was built on. Even so, the app was built and tested completely, and the first real run on the team's laptop worked.

Next time. In any app that depends on an AI or another online service, decide early what the user sees when that service is down or wrong. Build that path, and test it with a stand-in. You can then check it works without the real service and without spending credits.
